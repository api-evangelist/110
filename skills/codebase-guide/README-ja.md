# Codebase Guide

指定したディレクトリの構造、依存、主要フロー、設計傾向を整理し、コードベース理解用の Markdown レポートを生成するスキルです。

このスキルは品質監査ではなく、レビュー前のキャッチアップや新規参加者のオンボーディングに必要な情報を短時間で揃えることを目的にしています。

## Structure

- `SKILL.md` - スキル本体。分析対象、実行手順、出力要件、制約を定義
- `README.md` - このスキルの概要、構成、使い方
- `assets/` - レポート生成時に参照する補助資料
	- `template.md` - 出力レポートのテンプレート
	- `repo-context.md` - GitHub リポジトリ情報の生成先
- `scripts/` - 実行前の補助スクリプト
	- `init-repo-info.js` - `origin` と現在ブランチから `OWNER` / `REPO_NAME` / `BRANCH` を抽出

## Analysis Flow

1. `scripts/init-repo-info.js` を実行して、GitHub URL 構築に必要なリポジトリ情報を `assets/repo-context.md` に出力します。
2. 対象ディレクトリの構造を読み、レイヤー型、Feature 型、Utility 型、混合型のいずれに近いかを整理します。
3. 理解に重要なファイルを最大 10 件まで抽出し、読む優先度、役割、依存上の特徴を付けて提示します。
4. import 関係から依存方向、循環依存、横断依存、抽象依存と具体依存の傾向を説明します。
5. コードベースを代表する処理フローを 2 つ選び、開始地点、呼び出しチェーン、コアロジック、結果をコードスニペット付きで追跡します。
6. 設計思想、良い設計ポイント、改善ポイントを構造的根拠付きで整理します。
7. SOLID と理解容易性の観点で参考スコアを付け、レポートを Markdown で保存します。

## Output

- 出力ファイル名は `review-codebase-{directory名}.md`
- ファイルリンクは GitHub の `/blob/` URL を使用
- 関数、メソッド、クラス参照は `#Lstart-Lend` 付きのコードスニペットリンクを使用
- ディレクトリ構造セクションのみ `/tree/` リンクを使用し、ファイルは列挙しない
- 詳細な出力形は `assets/template.md` に従う

## Core Rules

- 推定には必ず確度と根拠を付ける
- 良い設計ポイントと改善ポイントには、最低 1 つ以上のコードスニペットリンクを含める
- 改善案は保守性だけでなく、開発スピード向上の観点も含める
- 感覚的な批評は避け、構造的な根拠に基づいて記述する
- `📁 ディレクトリ構造` 以降のファイル参照は、すべて GitHub URL に統一する

## Generated Artifacts

- `assets/repo-context.md` - 実行時のリポジトリ情報
- `review-codebase-{directory名}.md` - 生成されたコードベース理解レポート

## When To Use

- 大きめのディレクトリを読む前に、全体像を短時間で掴みたいとき
- レビュー対象の責務分割や依存方向を先に把握したいとき
- 新規参加者向けに、読む順番と代表フローをまとめたいとき
- リファクタ前に、設計上の強みと改善余地を俯瞰したいとき
